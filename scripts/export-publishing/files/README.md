## 1. 전달 범위

**이 폴더는 이식 검토를 위한 시각·상호작용 _제안_ 기준본이다. 제품 코드가 아니다.**

이 저장소의 Next 앱은 이미 `/api/admin/*` 에 연결돼 동작한다. 이 폴더는 그 화면들에 Clay 디자인 시스템을
입혔을 때 **어떻게 보이고 어떻게 반응하는지**를 보여 주는 별도 프로젝트다. 폴더를 넣는다고 제품 화면이 바뀌지 않는다.

⚠️ **이 저장소의 UI 기준선(`reference/`)과 정책 규범 서열을 대체하지 않는다.** `CONTRIBUTING.md` §1 은
"설계서 UI 와 다르면 안 된다 · 바꿀 이유가 있으면 `docs/OPEN-DECISIONS.md` 에 올려 판정"을 요구한다.
이 기준본을 제품에 적용할지는 **그 판정을 거친 뒤의 별도 작업**이고, 적용하더라도 `publishing/` 밖에서 한다.

## 2. 실행

```bash
cd publishing
npm ci
npm run dev          # http://localhost:5173 — GNB 맨 아래 「화면 목록」에서 전 화면으로 간다
npm test -- --run
npm run build        # dist/
```

검증 환경: Node 24.18 · npm. 루트 Next 앱과 의존성을 공유하지 않는 독립 프로젝트다.

## 3. 구조

```
publishing/
├─ src/
│  ├─ pages/babycube/     화면. 1화면 = 3파일
│  │    X.tsx             뼈대 — 레이아웃·상호작용
│  │    X.data.ts         도메인 — 타입·예시 데이터·라벨·포맷터 (API 가 들어올 자리)
│  │    X.test.tsx        동작 테스트
│  ├─ pages/gnbSections.tsx   GNB 메뉴 구성 (항목 id = 경로)
│  ├─ components/ui/      디자인 시스템 컴포넌트 38종
│  ├─ shadcn/ui/          shadcn 원본 층 (차트). 화면은 직접 쓰지 않고 components/ui 를 거친다
│  ├─ lib/                router(최소 구현) · cn · dataStatus · periodPresets
│  ├─ styles/tokens.css   Tailwind 진입 + 타이포 프리셋 + shadcn 브릿지
│  └─ tokens/_generated.css   토큰 빌드 산출물 (직접 수정 금지)
├─ tokens/                토큰 원본 JSON → `npm run build:tokens`
└─ docs/                  SCREENS · INTEGRATION
```

### 알아둘 규칙 (어기면 조용히 깨진다)

- **색은 semantic 토큰만** (`bg-surface`, `text-text-sub` …). hex·primitive(`bg-slate-900`) 금지. 주 버튼은 파랑이 아니라 near-black(`action-primary`)
- **타이포는 프리셋만** (`heading-2xlarge-bold`, `body-medium`, `metric-large` …). `text-sm` 류 금지
- **경계선·포커스는 `outline` + 음수 offset** — `border` 를 쓰면 레이아웃이 밀린다
- `src/lib/cn.ts` 는 **클래스를 병합하지 않는다** — 같은 속성 클래스를 두 곳에서 내보내면 둘 다 남는다. shadcn 층의 `src/lib/shadcn-utils.ts` (tailwind-merge) 와 섞지 말 것
- Tailwind 는 `src/styles/tokens.css` 의 `@source` 로 스캔 범위를 **명시**한다. 새 소스 폴더를 만들면 거기 등록해야 클래스가 생성된다
- 차트 계열색은 `CHART_SERIES_COLORS[i]` 상수로만. `` `var(--color-chart-series-${i})` `` 로 조립하면 배포 CSS 에서 빠진다
- 라우터는 `src/lib/router.ts` 의 최소 구현이다. 상세는 `App.tsx` 의 `DETAIL_ROUTES`(접두사 맵) — 화면이 경로 마지막 구간을 직접 읽는다

## 4. 실제 화면에 반영하기로 판정되면

적용 여부는 §1 의 판정 대상이다. 판정이 나면 `docs/INTEGRATION.md` 에 화면별로 **이 저장소의 기존 데이터 모듈(`src/data/*`)·API** 와의 대응을 적었다.
요지:

- 데이터 계약은 **기존 Next 앱의 것이 정본**이다. 퍼블의 `.data.ts` 타입에 서버를 맞추지 않는다
- 퍼블의 목록은 예시 배열을 **브라우저에서** 거르고 센다. 기존 앱은 `makeListApi` 로 **서버에서** 필터·정렬·페이지·상태 카운트를 받는다 — 퍼블의 필터 상태를 `ListQuery` 로 옮기면 된다
- 식별자 의미가 다른 화면이 있다 (회원·셀러). INTEGRATION 의 「식별자」 절을 먼저 볼 것
- 이 저장소의 `docs/PORTING-GUIDE.md` 는 **프로토타입 픽셀 동등 이식** 절차다. 이 기준본을 적용하는 절차가 아니다 — 정책 읽기·데이터 경계 같은 앞 단계만 그대로 유효하다

## 5. 원본 기획과 의도적으로 다른 부분

**색·레이아웃·간격·타이포는 원본 프로토타입이 아니라 Clay 디자인 시스템 토큰이다.** 이 폴더를 전달하는 이유가 그것이다.
원본에서 가져온 것은 도메인 내용(화면 구성·컬럼·상태 어휘·문구·정책)뿐이다.

그 밖에 원본과 다르게 둔 곳:

| 화면      | 원본                                | 퍼블                               | 이유                                                            |
| --------- | ----------------------------------- | ---------------------------------- | --------------------------------------------------------------- |
| 대시보드  | 계열별 합계 없음                    | 차트 계열 토글 칩에 기간 합계 표시 | 사용자 결정                                                     |
| 회원 상세 | 읽기 전용 값을 회색 비활성 입력칸에 | `InfoList`(읽는 값 형태)           | 고칠 수 있을 것처럼 읽히지 않게. 실제로 고치는 값은 상태 하나뿐 |

### 원본 정책을 화면이 강제하는 곳 (차이가 아니라 원본을 따른 것)

- 진행 중 렌트가 있는 회원은 **휴면 전환 불가** — 상세·목록 일괄 처리가 같은 판정(`canSleep`)을 쓴다
- 탈퇴 회원은 상태 변경 불가
- **본사 계정**은 셀러 운영 값(수수료율 등)을 고칠 수 없다
- 입점 심사: **수수료율 없이 승인 불가**(신청서의 0 은 "제안 없음"이라 빈 칸으로 연다) · **반려는 사유 필수** · 승인요청 건만 심사 가능
- 목록 상태 카드에 [전체] 없음 · 진입 시 기본 상태 선택 (회원·셀러·입점 심사·상품)

⚠️ 이 가드들은 화면 표현일 뿐 **서버의 권한·금액 검증을 대신하지 않는다.** 정책이 충돌하면 `CONTRIBUTING.md` §2 의 규범 서열(도메인모델 현행 규칙 → 기능정책-정의서 → …)로 판정하고, 서버를 퍼블에 맞춰 바꾸지 않는다.

## 7. 알려진 이슈 · 미결

- **번들 크기** — recharts 포함 단일 청크 약 1.2MB. 기준본이라 코드 분할하지 않았다
- **남은 상세 화면** — `docs/SCREENS.md` C·D 절. 이후 같은 폴더에 추가 전달한다
- **`/care-claims` 화면 코드 미확인** — 이 저장소의 `src/lib/screens.ts` 에도 비어 있다
- **이 저장소의 화면 레지스트리** (`src/lib/screens.ts`) — `title` 다수가 `대시보드BO-SYS-001` 로 생성돼 있다 (생성 스크립트 문제로 보임). 퍼블과 무관하나 대조 중 발견해 적어 둔다

### 이 폴더를 갱신하는 규칙

1. `publishing/` 은 **읽기 전용 기준본**이다. 여기서 직접 고치지 않는다 — 고칠 것이 있으면 퍼블 담당에게 알린다
2. 갱신은 디자인 키트 저장소에서 **다시 추출**해 PR 로 올린다. 맨 위 「추출 기준」 커밋이 버전이다
3. 갱신 전, 직전 전달 이후 이 폴더가 바뀌었는지 확인한다 — 커밋된 수정과 아직 커밋 안 된 수정 둘 다:
   `git log <직전 전달 커밋>.. -- publishing/` · `git status --short --untracked-files=all -- publishing/`
   바뀌었으면 멈추고, 그 수정을 원본에 반영할지 먼저 정한다 (폴더를 통째로 교체하면 그 수정이 조용히 사라진다)
