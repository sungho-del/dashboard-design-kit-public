## 0. 판정 — 가장 작은 변경

**새 UI 부품(39번째)은 만들지 않는다.** 바뀌는 것은 셋이다.

| #   | 무엇                                                                                      | 층                       | 왜 여기인가                                                                                                      |
| --- | ----------------------------------------------------------------------------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 1   | `AppShell` 에 **`topBar` 슬롯** — 줄의 틀(높이·여백·정렬·아래 선)은 셸이 그린다           | `components/ui/AppShell` | PageHeader 와 축을 맞추는 값(gutter 40 · 안쪽 그림자 선)을 한 곳에서 보장. 개발 임시 바의 `border-b` 도 사라진다 |

### 한 곳에서 넣는 방법 — 코드 확인 결과

- `AppShell` 이 받는 것은 `sidebar` · `header` · `maxWidth` · `children` 뿐이다(`AppShell.tsx:4-33`).
- **`APP_CHROME` 을 모든 화면이 넘기고 있지 않다.** 쓰는 곳은 `babycube/DashboardPage.tsx:533` 하나(PageHeader `actions`). `SELLER_APP_CHROME` 은 정의만 있고 쓰는 화면이 없다.
- 본사 화면은 공용 틀이 없다 — `<AppShell` 이 **59개 파일에 84번** 나오고 화면마다 `Gnb` 를 직접 넣는다. 셀러도 `SellerShell`(`seller/SettleParts.tsx:56`) 말고 `OrdersOverview` · `ProcessList` · `UnitDetail` · `SellerScreenIndexPage` 가 `AppShell` 을 직접 그린다 → `SellerShell` 한 곳만 고쳐서는 빠지는 화면이 생긴다.
- 모든 화면이 공통으로 지나는 곳은 **`src/App.tsx:284-288` · `src/SellerApp.tsx:233-237`** 뿐이다(이미 `ToastProvider` 를 감싸는 자리, 「전역 Provider + 경로 맵」 책임과 맞다). 로그아웃에 필요한 `navigate` 도 여기에 있다.
- 그래서: **진입점에서 Provider 로 한 번 넣고 `AppShell` 이 받아 그린다.** 화면 파일 59개는 손대지 않는다. 새 화면도 자동으로 줄이 나온다(「한 화면에만 넘기면 나머지에서 사라진다」가 구조적으로 일어나지 않는다).
- 버린 안: 화면마다 `topBar={...}` 를 넘기기 — 59개 파일 수정 + 새 화면이 빠뜨리면 조용히 사라진다. 본사 공용 틀을 새로 만들기 — 같은 59개 수정에 구조 변경까지.

## 정의

로그인한 계정이 누구인지(이름 · 역할) 보여 주고 로그아웃시키는, 콘텐츠 열 맨 위의 얇은 줄.

- 쓰이는 곳: 본사 어드민 모든 셸 화면 · 셀러 어드민 모든 셸 화면(2곳 · 같은 자리 같은 꼴)
- 규격 출처: **유추** — DESIGN.md §26·§D13 에 없다. 근거는 §24 PageHeader(gutter 40 · 안쪽 그림자 선 · `bg: surface`) · §1 Button small(32) · §26 Avatar small(24) · 개발 임시 바(`PubAdminShell.tsx:202-211`)

## Anatomy

```
┌──────── GNB ────────┬──────────────────────────────────────────────────────┐
│                     │                    ① (운) ② 운영관리자 · 본사 운영관리자  ③[로그아웃] │ ← 48
│                     ├──────────────────────────────────────────────────────┤ ← ④ 선
│                     │ PageHeader (72)                                       │
│                     ├──────────────────────────────────────────────────────┤
│                     │ 본문                                                  │
```

**줄(틀) — AppShell 이 그린다**

- 높이 **48 고정** · 좌우 여백 **40**(PageHeader·본문과 같은 gutter) · 내용 **오른쪽 정렬** · 세로 가운데 · 배경 `surface`
- ④ 아래 선: **안쪽 그림자 1px `border`** — PageHeader 와 같은 방식(§24). `border` 로 그리지 않는다(높이가 49 가 된다)
- 선이 두 겹이 되지 않는 이유: PageHeader 는 **아래 선만** 갖는다. 줄의 아래 선 = 줄과 PageHeader 의 경계 하나뿐
- 자리: 콘텐츠 열 안 · `header` 슬롯 **위**. GNB 는 덮지 않는다
- **고정하지 않는다(스크롤과 함께 올라간다)** — 지금 어떤 화면도 PageHeader 를 `sticky` 로 쓰지 않는다(전부 흐름). 나중에 PageHeader 를 `sticky` 로 켜는 화면이 생겨도 `top: 0` 그대로 맞는다(줄이 먼저 올라가고 머리가 붙는다) → `stickyTop` 보정 불필요

**계정 묶음 — 줄 안의 내용(요소 간격 12 · 아바타↔글자 8)**

- ① 아바타 (필수) — `Avatar` **small(24)** · 이름 첫 글자. 장식이다(접근성 절)
- ② 계정 글자 (필수) — 한 줄 「{이름} · {역할}」
  - 이름: `label-medium-bold` · `text`
  - 가운뎃점과 역할: `label-medium` · `text-sub` (역할이 여럿이면 develop 처럼 「 · 」로 이은 문자열 하나로 받는다)
  - 글자 묶음 최대 폭 **320** · 넘치면 **끝 말줄임**(이름·역할을 한 덩이로 자른다) · 전체 문자열을 `title` 로 준다
- ③ 로그아웃 (필수) — `Button` **secondary · small(32)** · 글자 「로그아웃」 · 아이콘 없음. 줄어들지 않는다

높이 48 의 근거: small 버튼 32 + 위아래 8. 개발 임시 바는 56 인데, 모든 화면이 세로를 내는 줄이라 4px 격자에서 버튼이 답답하지 않은 최소값을 골랐다(PageHeader 72 보다 확실히 낮아 위계가 선다).

## 접근성

- 줄은 **이름 있는 영역** 하나: `region` · 이름 **「로그인 계정」**. `<header>`/banner 로 만들지 않는다 — PageHeader 가 이미 `<header>` 라 banner 가 둘이 된다.
- 읽히는 순서 = DOM 순서 = **GNB → 계정 줄 → 페이지 머리 → 본문**.
- 아바타는 **장식**(스크린리더에 숨김). `Avatar` 는 이니셜일 때 스스로 `img` + 이름을 내므로, 숨기지 않으면 「운영관리자, 운영관리자 · 본사 운영관리자」로 이름이 두 번 읽힌다.
- 계정 글자는 한 문자열로 읽힌다: 「운영관리자 · 본사 운영관리자」. 말줄임돼도 읽히는 문자열은 전체다.
- 버튼 이름 「로그아웃」(보이는 글자 그대로).
- 색만으로 전하는 정보 없음. 라이브 리전 불필요(값이 저절로 바뀌지 않는다). 셀러 알림은 기존 `Toast` 가 알린다.
- 대비: `text`·`text-sub` on `surface` — PageHeader 제목·설명과 같은 조합.

## 하지 말 것

1. **화면 파일에서 `topBar` 를 넘기지 않는다.** 넘긴 화면에서만 보이는 로고 사고와 같은 꼴이 된다 — 끄는 경우(`null`)만 예외.
2. **줄에 다른 것을 얹지 않는다**(화면 제목 · 검색 · 알림 종 · 빵부스러기). 제목은 PageHeader 것이고, 얹는 순간 PageHeader 와 역할이 겹친다. develop 옛 상단바가 제목을 여기 뒀던 꼴로 돌아가지 않는다.
3. **아래 선을 `border` 로, 줄을 `<header>` 로 만들지 않는다** — 높이 1px 밀림 · banner 중복.
4. 아바타·이름을 버튼처럼 보이게(hover 면 · 포인터) 하지 않는다 — 갈 곳이 생기면 그때 메뉴로 설계한다.
