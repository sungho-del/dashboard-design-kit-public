# pipeline-architecture.md — 올인원 파이프라인 아키텍처

> 기획서 하나를 입력으로 **서비스 분석 → 화면 생성**까지 이어 돌리는 하네스의 마스터 규약.
> 실행 방식은 **단계별 체크포인트**(승인 게이트)다.

> ## ⚠️ 이 폴더의 파이프라인은 **Stage 1 → 5 두 단계다**
>
> 브랜드(2a·2b·3)와 Figma(4) 단계는 **이 폴더에서 삭제했다**(에이전트·커맨드 모두).
> 아래 §5 가 기록하듯 그 단계들은 "구현됨"이지만 실제로 돌리면 문서 표류로 빌드가 깨졌고,
> **대시보드 제작 경로는 애초에 그 단계를 거치지 않는다**(01 만 있으면 Stage 5 가 돈다).
>
> ```
> 기획서 → [Stage 1] 서비스 분석 → 01-service-brief.json
>                                      ↓
>        → [Stage 5] 화면 생성   → 05-screen-plan.json → src/pages/*
>                                      ↓
>        → npm run build → vercel deploy → 공유 링크
> ```
>
> 아래 본문의 Stage 2~4 서술은 **복구할 때를 위한 기록**으로 남겨 둔다.

## 실행 시작 (사용자 시나리오)

1. GitHub 기획서 ZIP을 받아 **`_plan/`에 압축 해제**
2. Claude 대화에 **`프로젝트 작업 진행 시작`** 입력
3. `/run-pipeline`이 `_plan/`을 입력으로 Stage 1부터 자동 실행 — **체크포인트마다 정지·질문**

## 0. 실행 모델

```
[입력] 기획서 (URL 또는 파일)
   │
   ▼
Stage 1 · 서비스 분석 (@agent-service-analyzer)
   → pipeline/01-service-brief.json (+ .md 요약)
   ▣ 체크포인트 1: 분석 결과 검토·승인
   │
   ▼
Stage 2 · 브랜딩 구축 (`brand-builder`(제거됨))
   → pipeline/02-brand-guide.json (+ .md 요약)
   §10 팔레트 프로토콜 실행 → tokens/primitive 갱신안 포함
   ▣ 체크포인트 2: 브랜드 방향·팔레트 검토·승인
   │
   ▼
Stage 3 · 디자인 시스템 반영 (`brand-applier`(제거됨))
   02 팔레트 → tokens/primitive/*.json → npm run build:tokens → DESIGN_참고.md §1-2 갱신
   (컴포넌트/스토리는 이어서 기존 엔진: /gen-story, figma-implementer)
   ▣ 체크포인트 3: 토큰·문서 검토·승인
   │
   ▼
Stage 4 · Figma 설계 (`figma-designer`(제거됨), 설계 전용 — 쓰기 실행은 차후)
   → pipeline/04-figma-plan.json  (라이브러리 변수·컴포넌트·화면 계획)
   ▣ 체크포인트 4: Figma 실행 계획 검토
   │
   ▼
Stage 5 · 화면 생성 (@agent-screen-builder)
   01.keyScreens → 유형 판정 → pipeline/05-screen-plan.json
   ▣ 체크포인트 5: 어떤 화면을 어느 템플릿으로 만들지 검토·승인
   → src/pages/*.tsx + *.data.ts + *.test.tsx  (실제 화면 코드)
```

> **Stage 5 는 브랜드 단계(2a·2b·3)에 의존하지 않는다.** 01 만 있으면 실행된다 —
> 색이 아직 Clay 기본값이어도 화면은 나온다. 브랜드를 먼저 입히고 싶으면 `/apply-brand` 후에 돌린다.
> 이렇게 끊어둔 이유: 브랜드 확정은 사람 판단이 여러 번 필요한데, **화면 골격은 그걸 기다릴 이유가 없다.**

## 1. 단계 간 계약 (핵심 원칙)

1. **각 Stage는 `pipeline/`의 이전 산출물만 읽는다.** 대화 맥락에 의존하지 않는다 →
   어느 세션에서든 특정 Stage만 독립 재실행 가능.
2. 산출물은 **JSON(기계 계약) + MD(사람 검토용 요약)** 한 쌍. 스키마는 `docs/schemas/`.
3. 체크포인트에서는 (a) 산출물 요약 (b) 판단이 필요한 지점 (c) "승인/수정" 질문을 보고한다.
   승인 전에는 다음 Stage로 넘어가지 않는다.
4. **상류 산출물이 바뀌면 하류는 재검토 대상.** 01이 바뀌면 02~04를 다시 확인하고,
   재실행하지 않기로 했다면 그 사유를 산출물 MD에 기록한다.
5. 추측 금지 — 기획서에 없는 정보는 지어내지 않고 `gaps`에 기록한다.

## 3. 명령어

- `/analyze-plan <URL|파일>` — Stage 1 단독 실행 (기획서 → 화면 목록)
- `/build-screens [화면id]` — **Stage 5 단독 실행 (화면 코드 생성). 01만 있으면 된다**
- `/run-pipeline [경로]` — 1 → 5 실행(기본 입력 `_plan/`), 체크포인트마다 정지
- `/build-tokens` — 토큰 JSON → CSS 빌드
- `/design-audit` — 디자인 토큰 준수 감사

> 덜어낸 커맨드: `/define-brand` `/build-brand` `/apply-brand` `/design-figma`
> `/implement-figma` `/check-tokens` `/gen-story` `/gen-all-stories` (삭제됨)

- 트리거 문구 **"프로젝트 작업 진행 시작"** = `/run-pipeline` 실행

## 4. Stage 1 상세 — 서비스 분석

- 기획서가 JS 렌더링 프로토타입이면 정적 fetch로 전체를 못 읽을 수 있다.
  이 경우 하위 페이지·에셋 fetch를 시도하고, 그래도 부족하면 `meta.coverage: "partial"` +
  `meta.gaps`에 못 읽은 영역을 기록하고 사용자에게 보완 방법(HTML 저장본, 스크린샷)을 요청한다.
- `brandInputs` 필드는 `DESIGN_참고.md` §10-A의 5문항(산업군·인상·행동·UI톤·컬러 역할)을
  기획서 근거로 채운다 — **Stage 2의 직접 입력**이 된다. 근거 없는 항목은 null + gap 처리.

### 5-1. Stage 1 실전 검증 기록 (2026-08-24)

그전까지 `01-service-brief.json` 은 **사람이 스키마를 보고 손으로 쓴 것**이었다.
즉 Stage 1 이 진짜 기획서를 읽어낼 수 있는지는 **한 번도 확인된 적이 없었다.**
운영 중인 어드민(Next.js, 클라이언트 렌더링)을 URL 로 넣어 처음으로 실측했다.

| 항목        | 결과                                                            |
| ----------- | --------------------------------------------------------------- |
| 입력        | 배포된 어드민 URL 1개 (로그인 벽 없음)                          |
| 추출 결과   | 화면 **28** · 기능 21 · 플로우 7 · IA 9그룹 · 한글 문자열 807개 |
| 스키마 검증 | `missing: []` · `badRefs: []` · 중복 화면 ID 0 · 고아 화면 0    |
| coverage    | `partial` — 상세형 화면이 원본에 구현돼 있지 않아 gaps 8건 기록 |

**여기서 배운 것 (에이전트 정의에 반영 완료)**

1. **본문이 빈 SSR 셸이어도 포기할 필요가 없다.** 라우트는 HTML `href` 에, 실제 기획 내용은
   JS 번들에 남는다. 메뉴는 대개 `{id,icon,label,badge,route}` 객체 리터럴 그대로 살아 있어
   IA 를 통째로 준다.
2. **번들을 통째로 `Read` 하면 컨텍스트가 터진다.** `grep -o` 로 패턴만 뽑아야 한다.
3. **인접 grep 은 매핑 방향을 알려주지 않는다.** `"톤","라벨"` 인지 `"라벨","톤"` 인지
   한 건은 원문 컨텍스트로 확인하고 전체에 적용해야 한다 (실제로 한 번 뒤집혀 나왔다).
4. **종착 안내가 Stage 2 만 가리키면 안 된다.** 대부분은 화면을 보려고 돌리는데
   브랜드 단계로 유도되고, 위 표의 2b·3·4 결함에 막혀 화면을 한 장도 못 본 채 끝난다.
   → 보고문을 `A) Stage 5 직행 / B) Stage 2a 브랜드` 2지선다로 고쳤다.
