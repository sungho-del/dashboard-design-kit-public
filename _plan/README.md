# \_plan/ — 기획서 입력 폴더

파이프라인 **Stage 1(서비스 분석)** 이 이 폴더를 읽는다.
넣고 나서 대화에 **`프로젝트 작업 진행 시작`** 이라고 입력하면 된다.
(비전문가용 안내는 루트의 `START-HERE.md`)

## 무엇을 넣을 수 있나

예전 이 문서는 "GitHub ZIP" 하나만 안내했는데, **Stage 1 은 그보다 넓게 받는다.**
아래는 `@agent-service-analyzer` 가 실제로 처리하는 형태다.

| 형태                    | 넣는 법                                         | 검증 상태    |
| ----------------------- | ----------------------------------------------- | ------------ |
| **웹 주소(URL)**        | 폴더에 넣지 말고 대화에 주소를 준다             | ✅ 검증됨    |
| **동작하는 프로토타입** | ZIP을 이 폴더에 압축 해제 (`index.html`·`*.js`) | ✅ 검증됨    |
| 워드·한글·PDF 기획서    | 파일 그대로 복사                                | 지원(미검증) |
| 노션·구글독스           | PDF로 내보내 복사                               | 지원(미검증) |
| 화면 캡처 이미지        | 이미지 파일 복사                                | 지원(미검증) |
| 마크다운·텍스트         | `.md` / `.txt` 로 복사                          | 지원(미검증) |

> **"검증됨"의 근거**: Next.js 로 만든 운영 어드민(SSR + 클라이언트 렌더링)을 URL로 넣어
> 화면 28개·기능 21개·플로우 7개를 추출했다. 본문이 비어 보이는 JS 앱이어도,
> Stage 1 이 라우트와 번들을 훑어 메뉴·컬럼·상태 어휘를 뽑아낸다.

## 규칙

- **한 번에 하나.** 여러 기획서를 섞어 넣지 말 것 (하위 폴더로 나눠 두면 어느 것을 쓸지 물어본다).
- 기획서에 **없는 내용은 만들어내지 않는다.** 못 읽은 영역은 산출물의 `meta.gaps` 에 남는다 — 거기를 보고 보완하면 된다.
- 여기 담긴 것은 **입력일 뿐 산출물이 아니다.** 하위 폴더는 `.gitignore` 에 걸려 있다(용량이 크고 외부 서비스 소스인 경우가 많다).

## 결과는 어디로 가나

`pipeline/01-service-brief.json`(기계 계약) + `.md`(사람 검토용).
**기존 파일이 있으면 덮어쓴다** — 이전 분석을 남기고 싶으면 미리 이름을 바꿔 백업할 것.

## 무엇이 잘 적혀 있어야 좋은 결과가 나오나

- 화면 목록 (메뉴 이름)
- 화면마다 무엇을 보여주는가 (표의 열 이름, 지표 항목)
- 상태 어휘 (접수/처리중/완료/취소 …)
- 버튼 라벨과 안내·경고 문구

색·폰트·여백·레이아웃은 **적을 필요 없다.** 그건 이 저장소의 디자인 시스템이 이미 갖고 있고,
기획서에 있더라도 **가져오지 않는다.**
