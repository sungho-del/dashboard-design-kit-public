입점사(셀러) 어드민은 별도 dev 서버(보통 http://localhost:5174)로 뜨고, HQ 앱은 안 떠 있는 경우가 많아 `src/pages/babycube/` 코드로 대조한다 (2026-11-04 검사 기준).

**보고하지 않는 것 (HQ 와 동일하거나 승인된 패턴):**

- 하단 sticky 액션 바(`Card sticky bottom-6`) 아래 24px 띠로 본문이 비쳐 보이는 것·스크롤 중간에 바가 본문을 가리는 것 — HQ 전 화면 공통. 끝까지 스크롤했을 때 24px 남는지만 본다
- 표 금액 우측 정렬 — DESIGN.md §7-2 "계산을 읽는 영역" 예외(정산·명세서·보증금 표). 단 우측 금액 바로 옆에 **좌측 정렬 열(날짜 등)** 이 붙으면 보고 대상
- 이미지 아래 `교체`·`삭제` gap-1(4px), 폼의 Input max-w-160 / Textarea max-w-195 폭 차이 — HQ 동일
- 목록 표 5+1 고정열 구성 — HQ 상품 목록과 동일 (단 열 폭 때문에 스크롤 창이 좁아지면 보고)

**자주 나오는 실제 결함 원인:** `Table` 이 `w-max` 라 `<col>` 폭을 안 준 열은 max-content 로 늘어나 1280 에서 상태·처리 열을 화면 밖으로 민다. 표마다 "폭 미지정 열 + 고정폭 합계 vs 976px(1280 콘텐츠 폭)" 를 먼저 잰다. 폭을 줘도 셀 안이 `truncate`(nowrap)면 최소 폭이 글 전체 길이라 같은 증상이다(2026-11-04 공지 내용 874px — `line-clamp-1` 로 고침).

**오른쪽 고정(sticky right) 처리 열이 있는 표** (셀러 정산·정산 명세 목록·세금계산서): colgroup 합이 1440 콘텐츠 폭(1136)에 딱 맞춰져 있어 1280(976)에서는 고정 열이 바로 앞 지급액·합계·상태 열을 **덮는다** — 넘침 열이 "화면 밖"이 아니라 "숫자 앞자리만 보임(「171,6」)" 으로 나타나 `hidden` 측정에 안 잡힌다. 고정 열 left 와 앞 열들의 left~right 를 비교해 "보이는 px" 을 잰다 (2026-11-05: 152·156·160px 넘침 → 높음).

**알려진 것(재보고 시 낮음·한 줄):** 셀러 상세 본사 행 「등록 상품수 412개」 vs 「등록 상품 (4)」 — 기획 확인 24번 대기(코드 주석). 상품 폼 배송비 「무료」 체크박스가 입력 중심보다 8px 위(등록·직영·입점 폼 공통). 한국어 음절 단위 줄바꿈(break-keep 은 일부 화면만).

**도구:** 풀페이지 스크린샷은 sticky 하단 바가 첫 뷰포트 바닥(y≈788)에 찍혀 본문을 가린 것처럼 보인다 — 끝까지 스크롤한 뷰포트로 따로 확인. 세금계산서 비활성 버튼 툴팁은 네이티브 `title` 이라 헤드리스로 못 본다. 스크래치 pw 폴더의 playwright-core 가 지워져 있으면 `%LOCALAPPDATA%/npm-cache/_npx/705bc6b22212b352/node_modules/playwright-core`(1.59.1 · chromium 1217) 를 파일 URL 로 import 한다.

**Why:** 같은 패턴을 매번 결함으로 올리면 게이트 신뢰가 떨어진다.
**How to apply:** 위 항목은 "HQ 동일/승인" 으로 한 줄 언급만 하고 순위 목록에서 뺀다. 헤드리스 셸은 오버레이 스크롤바라 소폭(수 px) 가로 넘침의 스크롤바 노출은 추정으로 표기한다.
