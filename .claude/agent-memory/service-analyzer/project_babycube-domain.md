BabyCube 는 유아용품 **렌트 + 판매** 멀티 셀러 마켓플레이스의 **본사** 운영 어드민이다.
디자인 결정에 직결되는 두 가지 구조가 있다.

**1. 렌트/판매 이원 구조가 색으로 표현된다.** 소스에서 렌트=`b-green`, 판매=`b-blue` 로 고정 배지.
거의 모든 목록 화면에 "유형" 칩 필터(렌트/판매)가 있고, 컬럼 세트도 유형에 따라 갈린다
(렌트가/보증금 vs 판매가). 판매자도 본사(`b-blue`)/셀러(`b-gray`)로 나뉜다.

**2. 상태 톤은 3종뿐이다.** `b-prog`(진행) · `b-done`(완료·중립) · `b-exc`(예외·경고).
상태 어휘는 130여 개지만 전부 이 3톤에 매핑된다. 부가 톤은 `b-green`/`b-blue`/`b-gray`/`b-gold`/`b-warn`.

**Why:** Stage 2 팔레트가 렌트·판매 대비를 확보하지 못하면 이 서비스의 가장 빈번한 시각적 구분이 무너진다.
또 상태 톤을 3종보다 잘게 쪼개면 원본에 없는 구분을 발명하는 것이 된다.

**How to apply:**

- Stage 2 팔레트 설계 시 **렌트/판매 두 유형색 + 상태 3톤**을 필수 요구사항으로 넘긴다.
- Stage 5 에서 Tag tone 을 정할 때 `pipeline/01-service-brief.json` 의 `domainVocabulary.statusTones`
  를 직접 참조한다 — 상태별 톤이 이미 전수 정리되어 있으므로 새로 판단하지 않는다.
- 이 서비스의 정체성 플로우는 **반납 검수 → 보증금 판정 → 안심케어 보전**(UF2)이다.
  판매 커머스에 없는 흐름이라, 화면 예시를 만들 때 이 축을 빼면 서비스 성격이 사라진다.
