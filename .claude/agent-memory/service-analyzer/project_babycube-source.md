`_plan/babycube-admin/` 은 정적 기획서가 아니라 **Next.js(turbopack) 프로덕션 번들 저장본**이다.
`pages/*.html` 은 SSR 셸이라 본문 텍스트가 없고, 기획 내용은 전부 `chunks/*.js`(minified)에 있다.

**Why:** Stage 1 재실행이나 gap 보완 시 이 성격을 모르면 "본문이 비어 있다"고 판단해 partial로 조기 종료하게 된다.
실제로는 메뉴·상태·컬럼·필터가 모두 데이터 구조로 남아 있어 정확한 추출이 가능하다.

**How to apply:** 재분석 시 minified JS 를 통째로 Read 하지 말고 아래 기법을 쓴다.

- **화면 ↔ 청크 1:1 매핑**: 각 `pages/X.html` 이 참조하는 청크 집합을 구한 뒤,
  전체 페이지에서 **1회만 등장하는 청크**가 그 페이지 전용 청크다.
  (공유 7 + 페이지 전용 28 = 35). 이 매핑이 "구현된 화면 vs 라우트만 있는 화면"의 유일한 판별 근거다.
- **turbopack 인라인 주의**: 공용 모듈(예: 회원 테이블 컬럼)이 모든 페이지 청크에 중복 복사된다.
  단순 grep 으로 컬럼을 뽑으면 전 화면에 회원 컬럼이 섞여 나온다 — 페이지 전용 청크 기준으로 추출하고,
  전 페이지 공통 등장 문자열은 걸러야 한다.
- **상태→톤 맵의 방향**: `"라벨":"b-톤"` 이다. `"b-톤","라벨"` 로 인접 페어를 잡으면 **오정렬**된다.
  비인용 키(`판매중:"b-prog"`)가 94개로 인용 키(38개)보다 많으므로 두 패턴을 모두 뽑아야 전체가 나온다.
- **미저장 영역**: 스타일시트(`1ts4wttg4nykw.css`)와 상세/등록 라우트 구현은 저장본에 없다.
  색상값과 상세형 화면 구성은 이 소스에서 절대 나오지 않는다 — 추측하지 말고 gaps 유지.
