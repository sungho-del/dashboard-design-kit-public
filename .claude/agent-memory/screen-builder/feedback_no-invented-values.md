원본을 대조해 화면을 만들 때, **청크에 값이 없다는 것은 "지어내도 된다"는 뜻이 아니다.**
구조만 맞추고, 값 목록을 모르면 지금 데이터를 그대로 두고 보고서에 "값 출처 불명"이라고 적는다.

**Why:** 조정자가 실패 사례 셋을 지목했다 —
① 대시보드 상태 흐름을 원본 4단계 대신 **11단계로 부풀림**(그 값이 API 응답이라 청크에 없었고,
빈칸을 전 화면 공용 상태 어휘 목록 130여 개에서 끌어다 채웠다),
② 보증금 내역에 **원본에 없는 열 2개**를 만듦,
③ 목록 화면마다 **"오늘 신규 주문 128건 +12건" 류의 요약 카드**를 세움 — 원본 카드는
`statusCounts` API 가 주는 건수뿐이고 증감·비교 기준 문구는 어디에도 없었다.

**How to apply:**

- **증감(±%)·비교 기준 문구는 원본에 없으면 넣지 않는다.** `up`/`good` 두 축을 제대로 갈라도
  숫자 자체가 지어낸 것이면 소용이 없다. 건수는 **우리 데이터에서 세면** 표와 모순되지 않는다.
- 요약 카드가 필터를 겸할 때, 건수는 **그 축을 뺀 나머지 조건까지 적용한 결과**에서 센다.
  전체 데이터에서 세면 검색을 좁혀도 숫자가 안 변해 표와 어긋난다.
- **"우리에게 있는데 원본에 없는 것은 뺀다."** 열·상태·행 액션·안내 문구 전부 해당한다.
  템플릿에서 딸려 온 `배송 처리`·`환불 승인` 시트 버튼과 확인 모달이 대표적인 잔재다.
- 원본이 화면마다 **일관되지 않아도 그대로 따른다.** (예: 주문·반품 목록에는 유형 툴팁이
  있는데 취소 목록에는 없다.) 나란히 놓으면 어색해 보여도, 없는 문구를 지어 내는 것보다 낫다.
- 걷어낸 것은 **테스트로 못을 박는다** — `queryByRole(...).not.toBeInTheDocument()` 로
  지어낸 열 이름·버튼 이름·`/^[+-]\d+건$/` 패턴이 다시 기어드는 것을 막는다.
