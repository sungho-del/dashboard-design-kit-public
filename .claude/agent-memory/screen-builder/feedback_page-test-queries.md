페이지 `.test.tsx` 의 쿼리는 **내가 실제로 렌더한 이름**으로만 쓴다. 그럴듯한 이름을 짐작해서
쓰면 테스트가 통째로 빨갛게 되고, 원인이 화면이 아니라 테스트라서 시간이 두 배로 든다.

**Why:** 조정자가 배치 작업에서 반복해 나온 실패 두 가지를 지목했다 —
① `Pagination` 은 페이지 버튼에 **숫자만** 넣는데 `"2 페이지"` 로 찾은 경우,
② 붙인 적 없는 `"○○ 관리"` 형태의 `aria-label` 을 기대한 경우.

**How to apply:**

- 쿼리를 쓰기 전에 **그 이름을 만드는 코드가 있는지 확인한다.** 없으면 컴포넌트에
  `aria-label` 을 실제로 붙이거나 쿼리를 실물 이름에 맞춘다.
- 확인 순서: 내가 쓴 `.tsx` → 그 UI 컴포넌트의 `.tsx` → 그 컴포넌트의 `.test.tsx`
  (컴포넌트 테스트가 그 컴포넌트를 어떤 role·name 으로 찾는지가 가장 빠른 정답이다).
- 이름이 **실행 시점에 따라 바뀌는 자리**가 있다. 예: `DatePicker` 의 오늘 날짜 셀은
  react-day-picker 가 `"오늘, 2026년 8월 24일"` 처럼 접두어를 붙인다 →
  정확 일치 대신 **정규식 부분 일치**로 찾아야 어느 날 돌려도 통과한다.
- 같은 이름이 둘 이상이면 범위를 좁힌다 — `within(row)` · `within(dialog)` ·
  `<section aria-label>`(role="region") 안으로. 특히 **시트 푸터 버튼과 요약 대시 버튼**은
  이름이 겹치기 쉽다(둘 다 상태 라벨을 쓴다).
- 화면 하나를 끝낼 때마다 그 화면 테스트를 돌려 **통과시킨 뒤** 다음으로 간다.
