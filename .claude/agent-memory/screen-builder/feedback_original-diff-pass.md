이미 만든 화면을 **원본과 대조해 정돈**하는 작업은 생성 작업과 규칙이 다르다.
할 일은 채우는 것이 아니라 **덜어내는 것**이다 — 우리에게 있는데 원본에 없는 것을 뺀다.

**Why:** 조정자가 실패 사례 둘을 지목했다 — ① 대시보드 상태 흐름이 원본 4단계인데
공용 상태 어휘 목록(130여 개)에서 끌어다 **11단계로 부풀렸다**, ② 보증금 내역에 원본에 없는
열 2개를 만들었다. 둘 다 원인이 같다: **값이 API 에서 와서 청크에 없었고, 그 빈칸을 지어내 채웠다.**

**How to apply:**

- **청크에 값이 없다 = 지어내도 된다는 뜻이 아니다.** API 로 오는 화면은 청크에
  **구조(컬럼·필터·버튼·문구)만** 있다. 구조만 맞추고, 값 목록을 모르면 지금 데이터를 그대로 두고
  보고서에 **"값 출처 불명"** 이라고 적는다.
- 자주 걸리는 발명들: **요약 카드 + 증감(±%) + 비교 기준 문구**(원본에 없으면 넣지 않는다) ·
  원본에 없는 **필터 축**(특히 트리 표에 단계 필터를 달면 부모 없는 자식이 남아 계층이 깨진다) ·
  PageHeader **도움말 툴팁**과 그 내용 · 지어낸 라벨 어휘(원본이 `O`/`X` 인데 `인증`/`미인증`) ·
  원본에 없는 **검증 규칙**(월령 구간 겹침 금지 등 — 원본은 서버가 판정한다).
- **반대 방향도 본다.** 원본에 있는데 빠뜨린 것이 구조의 핵심일 수 있다 —
  카테고리의 렌트/판매 트리 전환, 관리 열의 순서 이동 ▲▼·`+ 하위`,
  보증금 내역의 **상품 이름 옆 안심케어 표식**(열이 아니라 표식이라 "없는 열"로 오해해 지웠었다),
  출처 칩 필터, 검색 조건 셀렉트가 그랬다.
- **문구가 정반대인 경우가 있다.** 안심케어 반려 결과를 "보증금은 차감 없이 종결됩니다"로
  적어 뒀는데 그건 **승인**의 결과였다(원본: "보전 대상에서 빠지고 **차감 판단으로 되돌아간다**").
  타입·린트·테스트가 전부 통과하는 종류의 오류다 — 모달 문구는 원본과 한 문장씩 대조할 것.
- **페이지 설정(props)을 반드시 읽는다.** 화면마다 다르다:
  `showStatusDashboard: !1`(대시를 끈 화면) · `chip.dash: !0`(칩 대신 카드) ·
  `defaultStat: "청구 접수"`(첫 화면이 **전체가 아니다**. 초기화도 거기로 돌아간다) ·
  `columns` 를 `stat === "승인"` 으로 분기하는 **조건부 열** ·
  `toolsLeft` 가 없어 **엑셀 다운로드가 아예 없는 화면**(공용 목록 셸을 안 쓰는 얇은 화면) ·
  `render: () => "-"` 로 **항상 `-` 만 그리는 `처리` 열**(쓰기 API 자체가 없는 읽기 전용 화면).
- 숫자가 **화면 안에서 모순되지 않게** 한다. `전체 상품 1,284개` 를 상수로 박아 두고 표에는 8행이면
  그 자체로 거짓말이다. 건수는 **지금 남아 있는 행에서 세게** 만든다.
- 구조를 바꾸면 테스트도 **새 계약을 검증하도록** 고친다. 지워서 통과시키지 않는다.
  걷어낸 것에는 `⚠️ 원본에 없어서 걷어낸 것 — 되살리지 말 것` 주석과
  "되살아나지 않는지" 테스트를 함께 남긴다(다음 세션이 같은 것을 또 만든다).
- 디자인은 여전히 100% Clay 다. 원본 CSS·클래스·색을 옮기지 않고, tone 은 §3-1 로 다시 판단한다.

## 2차 라운드(2026-08-26, 쿠폰·포인트·공지·FAQ·리뷰·문의 6화면)에서 확인된 것

**"덜어내기"가 압도적으로 많았다** — 6화면에서 뺀 것이 되살린 것의 두 배가 넘는다.
반복해서 나온 발명 다섯 가지(다음에도 여기부터 의심할 것):

1. **요약 카드의 증감(±)과 비교 기준 문구** — 6화면 중 2화면에 있었고 **둘 다 원본에 없었다.**
   원본 요약 타일은 **라벨과 값 두 줄이 전부**다
2. **원본에 없는 필터 축** — 쿠폰은 `filter: {}` 인데 조건 4개를, 포인트는 회원 등급 축을
   통째로 갖고 있었다(등급 어휘 4개가 **전 청크 grep 에 하나도 없었다**)
3. **PageHeader 안내 문장** — 6화면 전부에 있었고 원본 어드민에는 **페이지 설명문이 없다**
   (원본의 안내문은 전부 상태 툴팁이거나 별도 `note` 상자다)
4. **시트 푸터의 도메인 액션**(답글 등록·답변 등록·고정 토글·쿠폰 코드 복사) —
   전부 원본 목록에 없는 조치였다. 특히 **쿠폰 코드 복사는 원본 레코드에 코드 필드가 없었다**
5. **행 전체 클릭** — 원본에서 눌리는 것은 언제나 **한 열의 링크**(`className: "linkish"`)다

되살린 쪽에서 반복된 것: **제목 셀의 둘째 줄**(공지 본문 발췌 60자) ·
**태그마다 붙는 행 액션**(FAQ 카테고리 ✎/✕) · **탭마다 다른 컬럼**(문의: 고객 7열 / 셀러 5열) ·
**`(숨김)` 접두어**(리뷰) · **컬럼 순서**(공지: 게시 기간이 상태보다 앞).

상세 화면이 배치에 없어 링크가 갈 곳이 없을 때는 **미리보기 시트로 받되 푸터를 두지 않는다**
(`MemberListPage` 가 세운 선례). 푸터를 만드는 순간 없는 기능을 지어내게 된다.
