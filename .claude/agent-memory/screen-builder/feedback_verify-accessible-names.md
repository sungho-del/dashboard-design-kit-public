`getByRole(..., { name })` 의 이름을 **추측해서 쓰지 말 것.** 쿼리를 쓰기 전에 그 이름을
방출하는 컴포넌트 코드를 열어 확인한다.

**Why:** BabyCube Stage 5(2026-08-24)에서 `Pagination` 의 페이지 버튼 이름을 `"2 페이지"` 로
지어냈다. 실물은 `{item}` 을 그대로 출력해 **`"2"`** 였다. 한 번의 추측이 두 파일에서 실패 5건이
됐고, 그 중 3건은 "페이지 이동이 막혀서" 뒤따라 깨진 **상태색 검증**이라 원인이 한눈에 안 보였다.
코디네이터의 지적: "앞으로도 컴포넌트의 접근가능 이름을 지어내지 마라."

**How to apply:**

- 이름의 출처를 먼저 읽는다 — `label` prop, `aria-label`, 자식 텍스트 중 무엇인가.
  아이콘 버튼은 `label`, 페이지 버튼은 **자식 텍스트(숫자)** 다.
- 기존 테스트에 선례가 있으면 그것이 정답이다. 템플릿 `src/pages/OrderListPage.test.tsx` 가
  같은 컴포넌트를 어떻게 찾는지 먼저 본다.
- 같은 이름이 여러 곳에 있으면(요약 카드 라벨 == 표의 Tag 라벨) `within()` 으로 좁힌다.
  BabyCube 주문 목록에서 "연체중"이 요약 카드와 상태 Tag 양쪽에 있어 `getByText` 가 터졌다.
- **화면 하나를 끝낼 때마다 그 화면의 테스트만 돌려 통과시키고 다음으로 넘어간다**
  (`npx vitest run src/pages/<경로>/<화면>.test.tsx`). 배치 병렬 작업에서도 자기 파일만
  대상으로 하면 다른 배치와 충돌하지 않는다. 네 화면을 다 만든 뒤 한꺼번에 돌리면
  같은 실수가 네 배로 쌓인다.
