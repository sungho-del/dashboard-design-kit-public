변경분을 **세 축으로 검사하고 하나의 판정**을 냅니다.
검사를 못 돌렸으면 통과가 아닙니다.

## 세 축 — 서로 못 잡는 것을 나눠 본다

| 축     | 담당                  | 잡는 것                                      | **못 잡는 것**                        |
| ------ | --------------------- | -------------------------------------------- | ------------------------------------- |
| 1 정적 | `@agent-design-qa`    | 타입·린트·테스트·빌드·토큰·구조·접근성 8항목 | 화면이 어떻게 보이는지, 실제로 되는지 |
| 2 시각 | `@agent-ui-inspector` | 겹침·잘림·간격 부족·정렬 축 충돌·소속 모호   | 눌렀을 때 무슨 일이 일어나는지        |
| 3 기능 | `@agent-qa-e2e`       | 이동 도착·딥링크·지속성·뒤로가기·콘솔 에러   | 코드 품질, 픽셀                       |

> **왜 셋인가.** 실제로 이런 일이 있었다 — 테스트 1,775건이 전부 통과하는데
> 주문 상세의 **뒤로가기가 죽어 있었다.** 테스트는 `onNavSelect("order-list")` 가
> 불렸는지만 봤고, `"order-list"` 는 존재하지 않는 경로였다.
> **한 축만으로는 반드시 빠진다.**

## 어느 축을 돌릴지

| 변경 유형       | 정적 | 시각      | 기능       |
| --------------- | ---- | --------- | ---------- |
| UI·동작 모두    | 실행 | 실행      | 실행       |
| 스타일·토큰만   | 실행 | 실행      | 대표 1경로 |
| 라우팅·경로·GNB | 실행 | 생략 가능 | **필수**   |
| 공통 컴포넌트   | 실행 | 실행      | 대표 흐름  |
| 문서만          | 생략 | 생략      | 생략       |

**생략한 축은 이유를 보고에 적는다.** 조용히 빼지 않는다.

## 절차

1. **범위 파악** — `git diff --stat` 과 인자($ARGUMENTS)로 무엇이 바뀌었는지 본다.
   경로가 주어지면 그 화면, 없으면 변경 파일에서 영향 화면을 추린다.
2. **`@agent-design-qa`** 8항목.
3. **`@agent-ui-inspector`** — 개발 서버가 필요하다. 없으면 먼저 띄운다.
4. **`@agent-qa-e2e`** — 같은 서버를 쓴다.
5. **판정 통합** (아래 우선순위).

> 축끼리 결과를 기다릴 필요가 없으면 **함께 돌린다.** 2·3·4 는 서로 독립이다.

## 판정 — 네 가지뿐

| 판정          | 언제                                                |
| ------------- | --------------------------------------------------- |
| `pass`        | 필수 검사가 전부 통과 · 사람이 더 볼 것 없음        |
| `fail`        | 재현되는 결함이 하나 이상                           |
| `needs_human` | 자동으로 단정 못 할 시각·정책·외부 연동 판단이 남음 |
| `blocked`     | 서버·브라우저·계정이 없어 **검증 자체를 못 함**     |

**우선순위** — ① 하나라도 `fail` 이면 `fail` · ② 필수 축이 `blocked` 면 `blocked` ·
③ 수동 확인이 남으면 `needs_human` · ④ 그 밖에만 `pass`.

## ⚠️ 이 커맨드의 핵심 원칙

- **못 돌린 검사를 `pass` 로 바꾸지 않는다.** 도구가 없어 못 한 것은 `blocked` 다.
- **반대로 없는 도구를 제품 결함으로 적지 않는다.** 그것은 `SKIP` 이고 이유를 적는다.
- **세 에이전트 모두 파일을 수정하지 않는다.** 결함은 보고까지다 —
  검사하는 쪽이 고치면 자기 일을 스스로 통과시키게 된다.
- 실패를 재실행으로 숨기지 않는다. 환경 문제가 명백할 때만 한 번 재시도한다.
