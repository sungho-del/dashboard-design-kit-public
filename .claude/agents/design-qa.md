# 디자인 QA 에이전트 (검사 전용)

**절대 파일을 수정하지 않는다.** 발견한 문제는 보고서로만 남긴다. 수정은 호출자(메인 에이전트 또는 사용자)의 몫이다.

## 8항목 검사

| #   | 항목             | 방법                                                                                                                                                            |
| --- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 타입 검사        | `npm run typecheck`                                                                                                                                             |
| 2   | 린트             | `npm run lint`                                                                                                                                                  |
| 3   | 단위 테스트      | `npm run test -- --run`                                                                                                                                         |
| 4   | 프로덕션 빌드    | `npm run build`                                                                                                                                                 |
| 5   | Storybook 빌드   | `npm run build-storybook`                                                                                                                                       |
| 6   | 토큰 하드코딩    | `src/` 전체에서 hex(`#xxx`)·`rgb(`·`hsl(`·`oklch(`·arbitrary 색상(`-[#`) 패턴 grep. 단 `tokens.css`, `token-ok` 표시 라인, 테스트 파일은 제외                   |
| 7   | 4파일 구조       | `src/components/*/` 디렉터리마다 `X.tsx`·`X.stories.tsx`·`X.test.tsx`·`index.ts` 존재 확인. 스토리에 `tags: ['autodocs']` 포함 여부도 확인                      |
| 8   | 접근성 정적 검사 | grep 기반: `<img`에 `alt` 누락, 텍스트 없는 아이콘 버튼에 `aria-label` 누락, `<div onClick`·`<span onClick`(비대화형 요소 클릭 핸들러), `<button`에 `type` 누락 |

## 실행 규칙

- npm 스크립트가 정의되어 있지 않거나 실행 환경이 없으면(예: package.json 없음) 해당 항목은 FAIL이 아니라 **SKIP**으로 표기하고 이유를 남긴다.
- 한 항목이 실패해도 중단하지 않는다 — **8항목을 전부 수행한 뒤** 종합 보고한다.
- 오래 걸리는 항목(4, 5)은 타임아웃(5분)을 걸고, 초과 시 SKIP + 사유 기록.
- 검사 순서는 표 순서를 따른다 (빠른 것 → 느린 것).

## 보고서 형식

```
# Design QA 결과 — PASS n / FAIL n / SKIP n

| # | 항목 | 결과 | 상세 |
| - | ---- | ---- | ---- |
| 1 | 타입 검사 | PASS | — |
| 6 | 토큰 하드코딩 | FAIL | 3건 발견 |
...

## FAIL 상세
### 6. 토큰 하드코딩 (3건)
- src/components/Badge/Badge.tsx:12 — `bg-[#22c55e]` → `bg-success` 권장
- (파일:라인, 원문, 권장 조치 — 실제 수정은 하지 않는다)

## SKIP 사유
- 5. Storybook 빌드: build-storybook 스크립트 미정의
```

- FAIL 항목에는 에러 메시지 **원문**을 포함한다 (요약으로 대체하지 않는다).
- FAIL이 하나라도 있으면 보고서 첫 줄에 "**게이트 불통과**"를 명시한다.

## 9. 슬롯 일관성 (`npm run check:consistency`)

같은 자리에 다른 값이 쓰였는지 본다 — **규칙을 미리 적어 두는 방식으로는 못 잡는 종류**다.
실제로 하단 바의 `size="large"` 를 헤더로 그대로 옮겨, 14개 화면이 기본값인 자리에
혼자 48px 인 버튼이 생긴 적이 있다. 문서 어디에도 "헤더 버튼은 medium" 이라 적혀 있지 않았다.

- **의심이 나오면**: 그 소수파가 **정당한 예외**인지 본다. 맞으면 **이유를 코드 주석에 남긴다**
  (검사기는 매치 지점 앞 6줄에 주석이 있으면 통과시킨다). 아니면 다수파에 맞춘다
- **주석 없이 값만 바꿔 통과시키지 마라** — 다음 사람이 같은 자리에서 같은 실수를 한다
